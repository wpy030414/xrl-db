# Spec — 键值状态机

## 要构建什么

- **目标**：实现一个纯内存的 String 类型键值状态机，且它**既能单机使用，又能被 Raft 复制，无需任何改动**。
- **为什么需要**：这是数据的最终归宿。它的正确性直接决定了「不丢数据」这个承诺能否成立。
- **位置**：`src/kv/`，分三个文件：
  - `op.rs` — `WriteOp`，可复制的写操作
  - `store.rs` — `Store`，状态机主体
  - `glob.rs` — Redis 风格的键模式匹配

## 行为

### 两条不可动摇的约束

这两条是「同一份代码同时服务单机与集群」的全部秘密：

1. **所有写入口只接受 `WriteOp`，不接受 `Command`。** `WriteOp` 不含任何相对时间，从类型层面杜绝了「apply 时读时钟」这种破坏确定性的写法。
2. **所有方法都显式接收 `now_ms`，绝不读系统时钟。** 时间由调用方给出。

第 2 条的意义：单机模式下调用方传当前时刻；集群模式下由 leader 把时刻写进日志再传给各副本。状态机对此完全无感。

### 为什么写操作要单独有一个类型

Raft 要求状态机的 apply 必须是确定性的——同一份日志条目在各副本上重放必须得到相同结果。

而 `SET key value EX 60` 里的 `EX 60` 是**相对时间**。若各副本在重放时各自读时钟，算出的过期时刻就会不同，副本之间于是产生分歧。这类 bug 不会立刻暴露，只在某次快照或重启后表现为「两个副本数据不一样」。

解决办法是**由 leader 在写日志之前就把相对时间解析为绝对时刻**。`WriteOp` 就是这个解析后的形态。

### 过期策略

采用**惰性过期**：不主动扫描，而是在每次读取时判断键是否已过期。这样已过期的键在任何地方都不会被观察到——包括 `DBSIZE`、`KEYS`、`SCAN`、`TYPE`、`DEL` 的计数。

### 与 Redis 的语义对齐

| 命令 | 对齐的细节 |
|---|---|
| `SET NX/XX` | 条件判断发生在 apply 时；已过期的键视为不存在 |
| `DEL` | 已过期的键不计入删除数 |
| `EXISTS` | 重复的键重复计数（`EXISTS a a` 返回 2） |
| `MGET` | 缺失的键在结果中**占位为 null**，不跳过 |
| `APPEND` | 保留原有 TTL |
| `INCR` / `DECR` | 保留原有 TTL；溢出与非法整数分别报错 |
| `MSET` | 清除原有 TTL |
| `TTL` | 不存在返回 `-2`，无过期时间返回 `-1`；剩余秒数**四舍五入** |
| `EXPIRE` 非正数 | 等价于立即删除该键 |
| `KEYS` | 结果按键排序（Redis 不保证顺序，我们排序以求可预测） |

## 输入 / 输出

- **输入**：`WriteOp`（写）或具体的读命令参数，外加一个 `now_ms: u64`
- **输出**：`Reply`（协议层的响应类型）

状态机返回 `Reply` 而非自定义的中间类型，是因为**状态机正是决定「客户端应当看到什么」的地方**；把它拆成「状态机结果 → 协议响应」两段只会产生一层无意义的转换。

## 约束

- **不得**在状态机内部读取系统时钟——`kv::now_ms()` 是模块内唯一读时钟的地方，且仅供调用方使用。
- **不得**让写入口接受 `Command`。
- **不得**让任何方法 panic（含整数溢出、除零等）。
- 整数运算**必须**使用 `checked_*` 或 `saturating_*`。
- 键与值**必须**二进制安全，不得对内容做 UTF-8 假设或转义。
- `TTL` 的秒数**必须**四舍五入，否则刚设置的 60 秒 TTL 会立刻显示成 59。

## 边界条件

| 情况 | 行为 |
|---|---|
| 键恰好到期的瞬间 | 视为已过期（用 `>=` 而非 `>``） |
| `INCR` 一个非整数值 | 报 `ERR value is not an integer or out of range`，**且不修改原值** |
| `INCR` 导致 `i64` 溢出 | 报 `ERR increment or decrement would overflow`，不修改原值 |
| `SET ... EX 0` / `EX -1` | 报错，拒绝（与 Redis 一致） |
| `EXPIRE key -1` | 删除该键，返回 1 |
| `PERSIST` 一个本就无 TTL 的键 | 返回 0（未改动） |
| `APPEND` 一个不存在的键 | 等价于 `SET`，返回新长度 |
| 超大过期时间（如 `EX i64::MAX`） | 饱和到 `u64::MAX`，不得溢出 panic |
| 空 inline 行 / 空模式 | 由协议层处理；状态机不接收空命令 |

- [x] `SET` / `GET` 往返正确
- [x] `SET NX` 对已存在的键失败且不改动原值
- [x] `SET XX` 对不存在的键失败
- [x] 过期的键在 `GET` / `EXISTS` / `DBSIZE` / `TYPE` / `TTL` 中一律不可见
- [x] `TTL` 遵循 `-2` / `-1` / 剩余秒数三种约定，且 60 秒显示为 60 而非 59
- [x] `EXPIRE` + `PERSIST` 正确切换 TTL
- [x] `EXPIRE` 非正数等价于删除
- [x] `DEL` 不把已过期的键计入删除数
- [x] `EXISTS` 对重复键重复计数
- [x] `MGET` 缺失键占位为 null
- [x] `APPEND` 拼接正确且保留 TTL
- [x] `INCR` 创建不存在的键（从 0 起算）且保留 TTL
- [x] `INCR` 对非整数值报错且不改动原值
- [x] `INCR` 溢出被检测
- [x] `MSET` 清除原有 TTL
- [x] `KEYS` 正确匹配 glob，且结果有序
- [x] `SCAN` 一次完整遍历能取到全部键并正确终止
- [x] `SCAN` 尊重 `MATCH` 模式
- [x] `FLUSHDB` 清空全部数据
- [x] 同一串操作 + 同一串时刻 ⇒ 完全相同的结果（确定性）
- [x] glob 支持 `*` / `?` / `[abc]` / `[a-z]` / `[^abc]` / 转义
- [x] glob 的多个 `*` 能正确回溯
- [x] glob 对二进制键安全
- [x] `now_ms()` 单位是毫秒且不倒退

## 已知限制

- **惰性过期不回收内存**：已过期但未被访问的键会一直占用内存，直到被访问或覆盖。主动过期（定时采样清理）留待后续。
- **`SCAN` 游标语义与 Redis 不同**：这里用「排序后的下标」而非 Redis 的哈希桶位置。它满足「一次完整遍历能取到遍历期间始终存在的所有键」，但**不满足** Redis 承诺的「不会返回重复元素」——遍历期间若有键被删除，后续元素会前移，可能造成重复。
- **整数解析的一处细微差异**：本实现接受前导 `+`（如 `+5`）与前导零（如 `007`），Redis 的 `string2ll` 会拒绝。实践中极少出现，故未做额外处理。
